# 지도 기반 장소 탐색 및 여행 코스 추천 서비스 기획

## 1. 서비스 한 줄 소개

> **"어디 가지?"라는 고민이 시작되는 순간, 내 목적에 딱 맞는 장소를 지도 위에서 바로 찾아주고, 여행에서는 그 장소들을 자연스러운 하루의 코스로 이어주는 서비스.**

우리는 장소를 많이 보여주는 서비스가 아니다. 일상에서는 지금 가고 싶은 목적지 하나를, 여행에서는 하루의 흐름 전체를 — 나에게 정말 맞는 장소만 골라서 보여준다.

---

## 2. 문제 정의: 장소를 '찾는' 시간보다 '검수하는' 시간이 더 길다

카카오지도, 네이버지도 같은 기존 지도 서비스는 장소 검색 기능 자체는 매우 강력하다. 문제는 검색 이후다. 검색 결과에서 "내 목적에 맞는 장소"를 골라내는 일은 여전히 온전히 사용자의 몫으로 남아 있다.

사용자가 "카페"를 검색하는 순간을 생각해 보자. 같은 검색어라도 실제 목적은 전혀 다르다.

- 조용히 책을 읽고 싶은 사람
- 노트북 작업이나 공부할 공간이 필요한 사람
- 감성적인 분위기에서 시간을 보내고 싶은 사람
- 친구와 오래 대화하고 싶은 사람
- 차를 가져가서 주차가 편해야 하는 사람

"옷가게"도 마찬가지다. 누군가는 빈티지 옷가게를, 누군가는 스트릿 패션 매장을, 누군가는 편집샵이나 가성비 좋은 매장을 찾고 있다.

하지만 기존 지도 앱에는 이런 '목적'이 분류되어 있지 않다. 그래서 사용자는 다음과 같은 불편을 반복해서 겪는다.

- 검색 결과가 너무 많아 어디부터 봐야 할지 선택이 어렵다.
- 리뷰 수가 많거나 이미 유명한 장소가 주로 노출되는 경향이 있다.
- 검색 결과가 나의 실제 목적과 정확히 맞지 않는 경우가 많다.
- "독서하기 좋은 카페", "작업하기 좋은 카페", "감성카페" 같은 목적 기반 분류가 부족하다.
- 빈티지 옷가게, 편집샵, 조용한 술집처럼 세부 취향으로 장소를 좁히기 어렵다.
- 결국 사진, 리뷰, 위치, 주차 여부를 사용자가 하나하나 직접 확인해야 한다.
- 실제로 좋은 장소인데도 리뷰가 적다는 이유로 검색 결과에서 잘 드러나지 않는다.

결과적으로 사용자는 장소를 찾는 과정에서 **불필요한 검수와 비교를 반복**하게 된다. 우리가 해결하려는 문제가 바로 이 지점이다.

---

## 3. 우리가 해결하려는 방향

우리의 원칙은 한 문장으로 요약된다.

> 장소를 많이 보여주는 것이 아니라, 사용자에게 진짜 맞는 장소를 **줄여서** 보여준다.

이를 위해 우리는 다음과 같이 접근한다.

- **장소 데이터를 목적별·분위기별·편의성별로 정제한다.** "카페"라는 대분류에서 멈추지 않고, "공부하기 좋은 카페", "주차 가능한 카페"처럼 사용자의 실제 상황에 맞는 세부 카테고리로 분류한다.
- **일상에서는 목적지 1개를 정확히 찾게 한다.** 지금 당장 가고 싶은 장소를 지도 위에서 조건으로 좁혀 빠르게 결정할 수 있다.
- **여행에서는 여러 장소를 자연스러운 코스로 연결해 추천한다.**
- **마음에 들지 않는 장소는 그 자리만 다시 찾는다.** 추천 코스 전체를 다시 만드는 대신, 해당 슬롯만 재탐색해 교체할 수 있다.
- **이미 정한 장소는 고정한다.** 예약해 둔 숙소처럼 확정된 장소는 그대로 두고, 잘 모르는 장소만 추천받는다.
- **추천 기준을 다양화한다.** 리뷰 수나 인기도만 기준으로 삼지 않고, 사용자 취향 조사 데이터와 목적 적합도, 동선, 주차 편의성을 함께 반영한다.
- **검수의 번거로움을 줄인다.** 사진과 리뷰를 뒤지며 직접 확인해야 했던 정보를 서비스가 미리 걸러서 보여준다.

그리고 이 모든 것을 가능하게 하는 핵심이 다음 섹션에 있다. **일상 탐색과 여행 슬롯 교체는 동일한 목적 기반 장소 탐색 엔진 위에서 동작한다.**

## 4. 핵심 엔진: 목적 기반 장소 탐색 엔진

이 서비스는 "일상 기능"과 "여행 기능"이라는 별개의 앱 두 개를 묶은 것이 아니다. 본질은 하나의 엔진, 즉 **사용자의 목적에 맞는 장소를 찾아내는 엔진**이며, 일상과 여행은 이 엔진을 서로 다른 상황에서 사용하는 두 가지 방식일 뿐이다.

```text
일상 = 목적지 1개 탐색
여행 = 코스 추천 + 슬롯별 재탐색/교체
```

이 엔진은 장소를 대분류로 보지 않는다. 카페를 그냥 "카페"로 두지 않고, 사용자의 의도에 따라 이렇게 세분화한다.

```text
공부하기 좋은 카페
독서하기 좋은 카페
감성카페
대화하기 좋은 카페
주차 가능한 카페
```

**일상에서는** 이 엔진으로 목적지 1개를 찾는다.

```text
지도 열기
→ 카페 선택
→ 공부하기 좋음 선택
→ 조용함 선택
→ 주차 가능 선택
→ 조건에 맞는 카페 후보 확인
→ 목적지 1개 선택
```

**여행에서는** 같은 엔진이 코스 추천과 슬롯 교체에 사용된다.

```text
여행 코스 추천
→ 음식점 A → 카페 B → 관광지 C → 숙소 D
→ 카페 B가 마음에 들지 않음
→ 카페 슬롯만 선택
→ 감성적 + 조용함 + 다음 장소와 동선 좋음 조건 적용
→ 새로운 카페 후보 확인
→ 카페 슬롯 교체
```

이 구조가 주는 이점은 분명하다. 사용자는 일상에서 익힌 탐색 방식을 여행에서 그대로 사용하므로 새로운 사용법을 배울 필요가 없다. 서비스 입장에서도 하나의 엔진을 고도화할수록 일상 경험과 여행 경험이 동시에 좋아진다.

## 5. 목적 기반 장소 카테고리: 분류가 아니라 필터다

여기서 말하는 카테고리는 내부 데이터 분류 체계가 아니다. **사용자의 상황과 목적을 해결해 주는 필터**다.

기존 지도 앱에서 "카페"를 검색한 사용자는 이렇게 움직인다.

1. 사진을 보고 분위기를 확인하고
2. 리뷰를 읽으며 조용한지 확인하고
3. 콘센트가 있는지 후기를 뒤지고
4. 주차 가능 여부를 다시 검색하고
5. 그제서야 "여기가 내 목적에 맞는 곳인지" 판단한다.

우리 서비스는 이 과정을 뒤집는다. 처음부터 사용자의 목적에 맞게 장소를 좁혀서 보여준다.

- 오늘은 조용히 책 읽고 싶다 → **독서하기 좋은 카페**
- 공부할 공간이 필요하다 → **공부하기 좋은 카페**
- 데이트 장소가 필요하다 → **분위기 좋은 감성카페**
- 노트북 작업이 필요하다 → **작업하기 좋은 카페**
- 차를 가져가야 한다 → **주차 가능한 카페**
- 빈티지한 옷을 사고 싶다 → **빈티지 옷가게**
- 개성 있는 옷을 찾고 싶다 → **편집샵**
- 혼자 부담 없이 밥을 먹고 싶다 → **혼밥하기 좋은 음식점**
- 2차 장소를 찾고 있다 → **분위기 좋은 술집**

| 사용자 상황 | 추천 카테고리 |
| --- | --- |
| 조용히 책을 읽고 싶을 때 | 독서하기 좋은 카페 |
| 공부할 공간이 필요할 때 | 공부하기 좋은 카페 |
| 사진 찍기 좋은 곳을 찾을 때 | 감성카페 |
| 노트북 작업을 해야 할 때 | 작업하기 좋은 카페 |
| 차를 가져갈 때 | 주차 가능한 카페 |
| 친구와 오래 대화하고 싶을 때 | 대화하기 좋은 카페 |
| 빈티지한 옷을 사고 싶을 때 | 빈티지 옷가게 |
| 개성 있는 옷을 찾고 싶을 때 | 편집샵 |
| 혼자 밥을 먹을 때 | 혼밥하기 좋은 음식점 |
| 가족과 함께 갈 때 | 가족 모임하기 좋은 음식점 |
| 2차 장소를 찾을 때 | 분위기 좋은 술집 |

사용자에게 필요한 것은 더 많은 검색 결과가 아니라, "내 상황"이라는 몇 번의 선택만으로 원하는 장소에 도달하는 경험이다.

## 6. 일상: 지도 기반 목적지 탐색

일상 모드는 코스를 만드는 기능이 아니다. **지금 당장 가고 싶은 목적지 1개**를 더 정확하게 찾는 지도 기반 탐색 기능이다.

사용 방식은 네이버지도나 카카오지도와 같다. 지도를 열고 장소를 찾는다. 다른 점은 검색과 카테고리가 목적 중심으로 세분화되어 있다는 것이다.

예를 들어 카페를 찾을 때:

```text
지도 열기
→ 카페 선택
→ 공부하기 좋음 선택
→ 주차 가능 선택
→ 현재 위치와 가까움 선택
→ 조건에 맞는 카페 후보 확인
→ 목적지 1개 선택
```

옷가게를 찾을 때:

```text
지도 열기
→ 옷가게 선택
→ 빈티지 선택
→ 가격대 선택
→ 현재 위치와 가까움 선택
→ 조건에 맞는 빈티지 옷가게 확인
→ 목적지 1개 선택
```

핵심은 사용자가 장소를 많이 보는 것이 아니라, **자신이 원하는 목적에 맞는 후보만 좁혀서 보는 것**이다. 조건을 하나 선택할 때마다 지도 위의 후보가 줄어들고, 마지막에는 고민 없이 선택할 수 있는 몇 개의 장소만 남는다.

## 7. 여행: 슬롯 기반 코스 추천

여행 모드에서는 여러 장소를 하나의 흐름으로 연결한 코스를 추천한다. 이때 코스는 **슬롯(slot)** 단위로 구성된다.

슬롯은 여행 코스 안에 들어가는 하나의 자리다. 예를 들어 하루 여행 일정을 만들 때 사용자는 다음과 같은 자리를 설정할 수 있다.

```text
음식점 → 카페 → 관광지 → 술집 → 숙소
```

각 슬롯은 사용자가 자유롭게 구성할 수 있다.

| 슬롯 종류 | 설명 |
| --- | --- |
| 음식점 | 점심, 저녁, 혼밥, 데이트 식사 등 |
| 카페 | 감성카페, 독서 카페, 작업 카페, 대화하기 좋은 카페 등 |
| 관광지 | 여행지, 전시, 체험, 산책 장소 등 |
| 술집 | 2차 장소, 분위기 좋은 술집, 조용한 술집 등 |
| 숙소 | 호텔, 펜션, 게스트하우스 등 |
| 주차장 | 목적지 주변 주차 공간 |
| 산책/휴식 | 공원, 해변, 강변, 조용한 휴식 장소 등 |

여기서 중요한 것은 **모든 슬롯을 앱에 맡길 필요가 없다**는 점이다. 사용자가 이미 정한 장소는 고정할 수 있다. 예를 들어 숙소를 이미 예약했다면 숙소 슬롯은 고정하고, 잘 모르는 음식점·카페·관광지·술집만 추천받는다. 추천은 사용자의 계획을 대체하는 것이 아니라, 비어 있는 부분을 채워 주는 역할을 한다.

## 8. 여행 코스 수정: 슬롯별 재탐색과 교체

추천 코스가 100% 마음에 드는 경우는 많지 않다. 기존 방식이라면 코스 전체를 다시 추천받거나, 지도 앱으로 돌아가 처음부터 다시 검색해야 한다.

우리 서비스에서는 **마음에 들지 않는 슬롯만 교체**한다. 그리고 이 교체 과정은 일상 모드에서 사용하던 목적 기반 장소 탐색 엔진 그대로다.

앱이 다음 코스를 추천했다고 가정하자.

```text
음식점 A → 카페 B → 관광지 C → 술집 D → 숙소 E
```

카페 B가 마음에 들지 않는다면, 전체 코스를 다시 추천받는 것이 아니라 카페 슬롯만 선택해서 원하는 조건을 하나씩 적용하며 다시 탐색한다.

적용할 수 있는 필터 예시:

- 감성적인 분위기
- 조용한 공간
- 독서하기 좋음
- 작업하기 좋음
- 주차 가능
- 현재 위치와 가까움
- 다음 장소와 동선이 좋음
- 가성비 좋음

```text
추천 코스 확인
→ 카페 B가 마음에 들지 않음
→ 카페 슬롯 선택
→ 감성카페 + 조용함 + 주차 가능 + 다음 장소와 동선 좋음 조건 적용
→ 조건에 맞는 카페 후보 확인
→ 새로운 카페로 교체
→ 기존 여행 코스에 반영
```

이 흐름이 의미하는 바는 분명하다. 사용자는 추천 코스를 그대로 따르는 것이 아니라, **추천을 출발점으로 삼아 자신의 목적에 맞는 여행 코스를 점점 완성해 간다.** 이 서비스는 단순한 자동 추천 서비스가 아니라, **추천 + 사용자 선택 + 지도 기반 탐색**이 결합된 서비스다.

## 9. 실제 사용 흐름

### 예시 1. 일상 — 공부할 카페 찾기

"오늘 공부할 카페를 가고 싶다"는 상황에서 앱을 연다. 지도에서 카페를 선택한 뒤 조건을 고른다.

```text
공부하기 좋음 + 조용함 + 콘센트 있음 + 주차 가능 + 현재 위치와 가까움
```

앱은 조건에 맞는 카페 후보만 지도 위에 표시한다. 수많은 카페를 직접 비교하지 않고도, 목적에 맞는 목적지 1개를 빠르게 선택할 수 있다.

### 예시 2. 일상 — 빈티지 옷가게 찾기

기존 지도 앱에서는 "옷가게"라고 검색한 뒤 사진과 리뷰를 보며 빈티지 매장인지 직접 확인해야 한다. 우리 서비스에서는 조건 선택으로 끝난다.

```text
옷가게 + 빈티지 + 현재 위치와 가까움 + 가격대 적당함
```

앱은 조건에 맞는 빈티지 옷가게 후보만 지도 위에 보여준다.

### 예시 3. 여행 — 부산 여행 코스 추천

부산 여행을 계획 중인 사용자를 가정하자. 숙소는 이미 예약했으므로 숙소 슬롯은 고정한다. 하지만 음식점, 카페, 관광지는 잘 모른다.

이때 앱은 회원가입 시 입력한 취향 조사 데이터를 기반으로, 사용자에게 어울리는 음식점·카페·관광지·술집을 추천한다.

```text
음식점 추천 → 감성카페 추천 → 관광지 추천 → 술집 추천 → 고정된 숙소
```

사용자는 이미 정한 장소는 유지하고, 잘 모르는 장소만 추천받아 여행 코스를 완성한다.

### 예시 4. 여행 — 마음에 안 드는 카페 교체

추천된 코스에서 카페가 마음에 들지 않는다. 사용자는 카페 슬롯만 선택해 일상 장소 탐색과 같은 방식으로 조건을 다시 적용한다.

```text
카페 슬롯 선택
→ 감성카페 선택
→ 조용함 선택
→ 주차 가능 선택
→ 다음 관광지와 가까운 곳 선택
→ 새로운 카페 후보 확인
→ 카페 교체
```

전체 여행 코스를 다시 만들지 않고, 마음에 들지 않는 부분만 자신의 목적에 맞게 바꾼다.

## 10. 장소 평가 기준

장소 추천은 리뷰 수나 평점만으로 결정하지 않는다. 다음 요소들을 점수화해 추천에 반영한다.

| 평가 기준 | 설명 |
| --- | --- |
| 위치 점수 | 현재 위치 또는 코스 동선과 가까운지 |
| 취향 적합도 | 사용자의 취향 조사 결과와 맞는지 |
| 목적 적합도 | 독서, 데이트, 혼밥, 작업, 쇼핑 등 목적과 맞는지 |
| 감성 점수 | 분위기, 인테리어, 사진 적합성 등 |
| 주차 편의성 | 자체 주차장 또는 주변 주차장이 있는지 |
| 가성비 | 가격 대비 만족도가 좋은지 |
| 동선 효율성 | 여행 코스에서 이전/다음 장소와 이동하기 좋은지 |
| 혼잡도 | 너무 붐비거나 대기 시간이 긴지 |

```text
추천 점수 =
취향 적합도 * 0.30
+ 목적 적합도 * 0.20
+ 위치/동선 효율성 * 0.20
+ 주차 편의성 * 0.15
+ 가성비 * 0.10
+ 감성 점수 * 0.05
```

이 계산식은 초기 기준이다. 서비스 출시 이후 사용자 피드백과 실제 이용 데이터를 축적하면서 가중치와 항목을 지속적으로 개선한다.

## 11. 주차 정보 제공

음식점, 카페, 관광지를 방문할 때 주차는 방문 자체를 좌우하는 조건이 되기도 한다. 그래서 장소를 추천할 때 다음 정보를 함께 제공한다.

- 장소에 자체 주차장이 있는지
- 주차 공간이 협소한지
- 주변에 공영주차장이나 유료주차장이 있는지
- 목적지와 주차장 간 거리가 가까운지
- 여행 코스 동선상 주차가 불편하지 않은지

특정 장소의 주차가 어렵다면 주변 주차장 후보까지 함께 연결해 준다. 예를 들어 자체 주차장이 없는 카페를 선택하면, 도보 거리의 공영주차장을 함께 안내하는 식이다.

이 기능은 단순히 장소를 추천하는 것을 넘어, **사용자가 실제 방문 과정에서 겪을 수 있는 불편까지 줄이는** 요소다. 추천은 장소를 고르는 순간이 아니라, 도착해서 만족하는 순간까지 이어져야 한다.

## 12. 서비스 차별점

기존 지도 앱과 비교했을 때 우리 서비스의 차별점은 다음과 같다.

- 검색 결과를 많이 보여주는 것이 아니라, 사용자의 목적에 맞게 **줄여서** 보여준다.
- 리뷰 수나 인기도에만 의존하지 않는다.
- 감성, 조용함, 독서, 작업, 주차 가능 여부, 빈티지, 편집샵처럼 **실제 방문 목적**을 반영한다.
- 일상에서는 지금 가고 싶은 목적지 1개를 지도 위에서 빠르게 찾을 수 있다.
- 여행에서는 여러 장소를 코스 단위로 연결한다.
- 일상과 여행이 **동일한 목적 기반 장소 탐색 엔진**을 공유한다.
- 추천된 여행 코스에서 마음에 들지 않는 슬롯만 일상 탐색 방식으로 다시 찾아 교체할 수 있다.
- 사용자가 이미 정한 장소는 고정하고, 모르는 장소만 추천받을 수 있다.
- 지도 기반 필터링을 통해 사용자가 직접 원하는 장소를 좁혀갈 수 있다.
- 주차 정보와 동선까지 함께 고려한다.

| 구분 | 기존 지도 앱 | 우리 서비스 |
| --- | --- | --- |
| 장소 탐색 방식 | 검색 결과를 많이 보여줌 | 목적에 맞는 후보만 좁혀서 보여줌 |
| 추천 기준 | 리뷰 수, 인기도, 광고, 알고리즘 영향 | 목적, 취향, 위치, 주차, 동선 등 종합 반영 |
| 카테고리 | 대분류 중심 | 사용자 상황 기반 세부 카테고리 |
| 일상 사용 | 장소 검색 후 직접 검수 | 목적지 1개를 필터링해서 빠르게 선택 |
| 여행 사용 | 장소를 개별적으로 찾아야 함 | 슬롯 기반으로 코스 추천 |
| 코스 수정 | 사용자가 직접 다시 검색 | 마음에 안 드는 슬롯만 재탐색 후 교체 |
| 핵심 가치 | 많은 정보 제공 | 필요한 정보만 정제해서 제공 |

## 13. 최종 목표

우리의 최종 목표는 사용자가 여러 지도 앱을 오가며 사진과 리뷰를 직접 검수하지 않아도 되는, **지도 기반 장소 탐색 및 여행 코스 추천 시스템**을 만드는 것이다.

> **우리는 장소를 '많이' 보여주는 서비스가 아니다.
> 사용자에게 정말 맞는 장소만 골라, 일상에서는 오늘의 목적지가 되게 하고, 여행에서는 자연스러운 하루의 코스가 되게 하는 서비스다.**

```text
정제된 장소 데이터

+ 동선 및 주차 정보 제공

```

일상과 여행은 별개의 기능처럼 보이지만, 실제로는 동일한 목적 기반 장소 탐색 엔진을 공유한다. 일상에서는 그 엔진으로 목적지 1개를 찾고, 여행에서는 그 엔진으로 코스를 구성하며, 마음에 들지 않는 슬롯을 다시 탐색해 교체한다. 이 하나의 구조가 서비스 전체를 관통한다.

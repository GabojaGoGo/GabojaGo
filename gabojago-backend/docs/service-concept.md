# 지도 기반 장소 탐색 및 여행 코스 추천 서비스 기획

## 1. 서비스 한 줄 소개

> **"어디 가지?"라는 고민이 시작되는 순간, 내 목적에 딱 맞는 장소를 지도 위에서 바로 찾아주고, 여행에서는 그 장소들을 자연스러운 하루의 코스로 이어주는 서비스.**

우리는 장소를 많이 보여주는 서비스가 아니다. 일상에서는 지금 가고 싶은 목적지 하나를, 여행에서는 하루의 흐름 전체를 — 나에게 정말 맞는 장소만 골라서 보여준다.

---

## 2. 문제 정의: 장소를 찾는 데서 끝나지 않는다 - 검수와 동선 조율까지 사용자의 몫이다

카카오맵, 네이버지도 같은 기존 지도 서비스는 장소를 검색하고 위치를 확인하는 데 매우 강력하다. 문제는 검색 결과가 나온 뒤부터다. 사용자는 단순히 장소 하나를 고르는 데서 끝나지 않고, 그 장소가 자신의 목적에 맞는지 검수하고, 여행이라면 다른 장소들과 실제로 갈 수 있는 순서로 다시 조합해야 한다.

자체 설문조사(122명 응답)에서도 이 문제가 분명하게 나타났다. 여행 계획에서 가장 오래 걸리거나 귀찮은 단계로 응답자의 29.5%는 **갈 만한 장소 찾기**, 23.0%는 **찾은 장소 중 진짜 괜찮은 곳을 고르기**, 23.8%는 **장소들의 동선과 순서 배치**를 꼽았다. 탐색, 검수, 동선 문제만 합쳐도 전체 응답의 76.2%다.

### 1) 같은 검색어라도 사용자의 목적은 다르다

사용자가 "카페"를 검색하는 순간을 생각해 보자. 같은 검색어라도 실제 목적은 전혀 다르다.

- 조용히 책을 읽고 싶은 사람
- 노트북 작업이나 공부할 공간이 필요한 사람
- 감성적인 분위기에서 시간을 보내고 싶은 사람
- 친구와 오래 대화하고 싶은 사람
- 차를 가져가서 주차가 편해야 하는 사람

"옷가게"도 마찬가지다. 누군가는 빈티지 옷가게를, 누군가는 스트릿 패션 매장을, 누군가는 편집샵이나 가성비 좋은 매장을 찾는다.

하지만 기존 지도 서비스는 대체로 업종, 거리, 리뷰 수, 인기도 중심의 검색 결과를 보여준다. 사용자의 구체적인 목적은 사진, 리뷰, 블로그, SNS를 직접 넘나들며 확인해야 한다. 결국 사용자는 검색 결과를 많이 받지만, 자신에게 맞는 장소를 찾기 위해 다시 긴 검수 과정을 거친다.

- 검색 결과가 너무 많아 어디부터 봐야 할지 어렵다.
- 리뷰가 많거나 이미 유명한 장소가 먼저 노출되기 쉽다.
- 사진과 후기를 여러 개 비교해야 실제 분위기와 목적 적합도를 판단할 수 있다.
- "독서하기 좋은 카페", "작업하기 좋은 카페", "빈티지 옷가게", "조용한 술집"처럼 세부 취향으로 좁히기 어렵다.
- 실제로 좋은 장소도 리뷰 수나 인지도가 낮으면 쉽게 발견되지 않는다.

### 2) 여행에서는 좋은 장소를 찾는 것만으로 충분하지 않다

여행은 좋은 장소 목록을 만드는 일이 아니다. 음식점, 카페, 관광지, 숙소처럼 서로 다른 장소를 **이동 시간과 방문 순서까지 고려해 하나의 하루로 연결하는 일**이다.

각 장소가 개별적으로 좋아도 코스로 묶이면 문제가 생긴다.

- 서로 멀리 떨어져 있어 이동 시간이 예상보다 길어진다.
- 식사 시간, 체크인 시간, 영업시간을 고려하지 못하면 일정이 비어 버린다.
- 웨이팅, 휴무, 날씨, 교통편 같은 현장 변수로 계획이 쉽게 무너진다.
- 동행의 취향과 컨디션이 달라지면 다시 처음부터 조율해야 한다.
- 마음에 들지 않는 장소 하나 때문에 코스 전체를 다시 짜야 하는 부담이 생긴다.

실제로 설문 응답자 중 58.2%는 1박 2일 기준 코스를 짜는 데 1시간 이상을 쓴다고 답했다. 계획대로 다니지 못한 이유로는 `지쳐서 또는 귀찮아져서`가 35.2%, `웨이팅·휴무 등 현장 변수`가 33.6%, `예상보다 긴 이동 시간`이 23.0%로 나타났다.

즉 여행자는 "어디가 좋은가"뿐 아니라 "이 장소들을 오늘의 내 상황에서 어떤 순서로 가야 하는가"까지 직접 판단하고 있다.

### 3) 사용자가 반복하는 일은 탐색, 검수, 조합, 재조정이다

현재 사용자는 보통 다음 과정을 반복한다.

```text
지도·SNS·블로그에서 후보 찾기
→ 사진·리뷰·주차·영업정보 직접 검수
→ 지도에서 위치를 다시 확인
→ 이동 시간과 순서를 직접 조합
→ 웨이팅·휴무·날씨·동행 의견으로 일정 변경
→ 바뀐 일정에 맞춰 다시 검색
```

문제는 장소 검색 기능이 부족한 것이 아니다. **목적에 맞는 후보를 줄이고, 검수 부담을 낮추며, 여러 장소를 실제로 실행 가능한 동선으로 연결하고, 변경된 한 자리만 다시 조정하는 과정**이 여전히 사용자에게 맡겨져 있다는 점이다.

우리가 해결하려는 문제는 다음과 같다.

> 사용자가 장소를 많이 찾는 문제가 아니라, 내 목적에 맞는 장소를 검수하고 여러 장소를 동선으로 조합하며 현장 변수에 따라 다시 조정하는 데 너무 많은 시간과 판단을 쓰는 문제.

따라서 가보자GO는 일상에서는 목적에 맞는 장소 후보를 빠르게 좁혀 주고, 여행에서는 사용자가 정한 슬롯과 고정 장소를 존중하면서 나머지 장소를 자연스러운 동선으로 연결한다. 또한 마음에 들지 않거나 갈 수 없어진 장소는 코스 전체가 아니라 해당 자리만 다시 찾고 교체할 수 있게 한다.

### 문제를 뒷받침하는 여행 조사 근거

국민여행조사는 사용자가 동선 계획에 불편을 느낀다는 사실을 직접 측정한 자료는 아니다. 대신 국내여행이 어떤 시간·동행·정보 탐색 조건에서 이루어지는지를 보여 준다. 이 조건은 자체 설문에서 확인한 탐색·검수·동선 부담이 왜 중요한 문제인지를 뒷받침한다.

| 조사 결과 | 객관적 해석 | 서비스 설계 시사점 |
| --- | --- | --- |
| 국내여행의 58.8%가 당일여행, 29.8%가 1박 2일이다. | 국내여행의 88.6%가 2일 이내의 짧은 일정이다. 이 수치만으로 동선 문제가 발생한다고 단정할 수는 없지만, 일정의 시간 여유가 크지 않다는 점은 확인된다. | 여행 코스 기능은 장소 수를 늘리는 것보다, 주어진 시간 안에 실행 가능한 순서와 이동 시간을 우선 계산해야 한다. |
| 관광여행의 방문지 선택 이유(1순위)에는 `여행할 수 있는 시간` 13.3%, `여행 동반자 유형` 11.0%가 포함된다. | 방문지 선택은 장소의 지명도나 볼거리만으로 결정되지 않으며, 남은 시간과 동행 구성도 실제 선택 요인이다. | 코스 추천 입력값에 여행 시간과 동행 조건을 포함하고, 동일한 장소라도 여행 맥락에 따라 다른 후보를 제시해야 한다. |
| 관광여행 동반자는 평균 3.7명이며, 동반자 유형은 가족 60.9%, 친구·연인 35.7%다. | 관광여행은 개인 단독 활동보다 동행이 있는 활동인 경우가 많다. 단, 이 수치가 동행 간 취향 충돌의 크기까지 보여 주지는 않는다. | 개인 취향 추천만으로 끝내지 않고, 함께 가는 사람과 고정된 장소를 반영해 코스를 조정할 수 있어야 한다. |
| 관광여행 정보 획득 경로(1순위)는 과거 방문 경험 37.2%, 주변인 27.5%, 인터넷 사이트·모바일 앱 16.8% 순이다. 인터넷·모바일 앱 이용자 중에서는 커뮤니티 게시판이 47.1%로 가장 높고, 지도·평가 정보는 10.9%다. | 여행 정보 탐색은 익숙한 경험, 주변인, 커뮤니티 등 여러 출처에 분산돼 있다. 이 통계만으로 기존 지도 서비스의 품질을 평가할 수는 없지만, 여행자는 추천의 근거와 신뢰도를 중요하게 판단할 가능성이 높다. | 추천 결과에 단순 순위만 보여 주지 않고, 왜 이 장소와 순서가 제안됐는지와 변경 시 어떤 제약이 달라지는지를 설명할 수 있어야 한다. |

이제 두 조사 결과를 함께 해석할 수 있다. 국민여행조사는 **짧은 일정, 동행, 시간 제약, 분산된 정보 탐색**이 국내여행의 일반적 조건임을 보여 준다. 자체 설문은 바로 그 조건에서 사용자가 **장소 탐색 29.5%, 장소 검수 23.0%, 동선·순서 배치 23.8%**를 가장 큰 계획 부담으로 느낀다는 사실을 보여 준다.

따라서 가보자GO의 필요성은 "더 많은 장소를 찾아주는 서비스"에 있지 않다. 목적에 맞는 후보를 먼저 줄이고, 사용자의 시간·동행·고정 장소를 반영해 실행 가능한 동선으로 연결하며, 현장 변수나 불만족이 생기면 코스 전체가 아니라 해당 슬롯만 다시 조정하게 하는 데 있다.

## 3. 우리가 해결하려는 방향

우리의 원칙은 한 문장으로 요약된다.

> 장소를 많이 보여주는 것이 아니라, 사용자에게 진짜 맞는 장소를 **줄여서** 보여준다.

이를 위해 우리는 다음과 같이 접근한다.

- **장소 데이터를 목적별·분위기별·편의성별로 정제한다.** "카페"라는 대분류에서 멈추지 않고, "공부하기 좋은 카페", "주차 가능한 카페"처럼 사용자의 실제 상황에 맞는 세부 카테고리로 분류한다.
- **일상에서는 목적지 1개를 정확히 찾게 한다.** 지금 당장 가고 싶은 장소를 지도 위에서 조건으로 좁혀 빠르게 결정할 수 있다.
- **여행에서는 여러 장소를 자연스러운 코스로 연결해 추천한다.**
- **마음에 들지 않는 장소는 그 자리만 다시 찾는다.** 추천 코스 전체를 다시 만드는 대신, 해당 슬롯만 재탐색해 교체할 수 있다.
- **이미 정한 장소는 고정한다.** 예약해 둔 숙소처럼 확정된 장소는 그대로 두고, 잘 모르는 장소만 추천받는다.
- **추천 기준을 다양화한다.** 리뷰 수나 인기도만 기준으로 삼지 않고, 사용자 취향 조사 데이터와 목적 적합도, 동선, 주차 편의성을 함께 반영한다.
- **검수의 번거로움을 줄인다.** 사진과 리뷰를 뒤지며 직접 확인해야 했던 정보를 서비스가 미리 걸러서 보여준다.

그리고 이 모든 것을 가능하게 하는 핵심이 다음 섹션에 있다. **일상 탐색과 여행 슬롯 교체는 동일한 목적 기반 장소 탐색 엔진 위에서 동작한다.**

## 4. 핵심 엔진: 목적 기반 장소 탐색 엔진

이 서비스는 "일상 기능"과 "여행 기능"이라는 별개의 앱 두 개를 묶은 것이 아니다. 본질은 하나의 엔진, 즉 **사용자의 목적에 맞는 장소를 찾아내는 엔진**이며, 일상과 여행은 이 엔진을 서로 다른 상황에서 사용하는 두 가지 방식일 뿐이다.

```text
일상 = 목적지 1개 탐색
여행 = 코스 추천 + 슬롯별 재탐색/교체
```

일상에서는 이 엔진으로 목적지 1개를 찾고, 여행에서는 각 슬롯에 들어갈 후보를 고르거나 교체한다. 두 상황의 구체적인 사용 흐름은 6~8절에서 설명한다.

이 구조가 주는 이점은 분명하다. 사용자는 일상에서 익힌 탐색 방식을 여행에서 그대로 사용하므로 새로운 사용법을 배울 필요가 없다. 서비스 입장에서도 하나의 엔진을 고도화할수록 일상 경험과 여행 경험이 동시에 좋아진다.

### 데이터 활용 구조: 종류·특성·목적을 분리해 같은 엔진에 쓴다

이 엔진은 하나의 카테고리에 모든 의미를 넣지 않는다. 장소의 **객관적 종류**, 확인 가능한 **특성값**, 사용자가 원하는 **방문 목적**을 서로 다른 데이터로 관리한다. 이 세 축을 분리해야 `중식은 제외` 같은 종류 조건과 `데이트` 같은 목적 조건이 섞이지 않고, 일상 탐색과 여행 슬롯에서도 같은 기준을 재사용할 수 있다.

| 데이터 축 | 역할 | 현재 기준과 고도화 방향 |
| --- | --- | --- |
| `PlaceSubtypeCode` | 장소가 무엇인지 나타내는 세부 종류 | 숙소·액티비티·술집·카페·음식점·상점·관광지의 7개 대분류 아래 64개 세부 종류를 둔다. 공공데이터의 업종·관광 분류를 이 체계에 매핑하고, 애매한 매핑은 검수 대상으로 남긴다. |
| `AttributeKey` | 장소가 어떤 조건을 갖는지 나타내는 특성값 | 주차·소음·혼잡도·가격대·운영시간 등의 공통 특성과 업종별 특성을 34개 필드로 관리한다. 값이 없는 경우도 추측으로 채우지 않고 `UNKNOWN`으로 기록하며, 데이터 정제와 운영 검수를 통해 보완한다. |
| `PlacePurposeCode` | 사용자가 왜 그 장소에 가려는지 나타내는 목적 | 현재는 데이트, 공부·작업, 가족 나들이의 목적 정의를 두고 있다. 이후 특성값 조합에 따른 판정 규칙을 설계·검수해 목적 카테고리를 부여하며, 목적 종류와 기준은 데이터 품질 검증 결과에 따라 확장한다. |

```text
공공 개방 데이터 확보
→ 상호·주소·좌표·업종·영업 상태 정제·표준화
→ Subtype으로 장소의 종류 분류
→ Attribute로 확인 가능한 특성값 구조화
→ 검수된 규칙에 따라 Purpose 판정
→ 일상 지도 필터와 여행 슬롯 후보 선정에 공통 사용
```

초기에는 행정안전부 지방행정 인허가데이터, 소상공인시장진흥공단 상가정보, 한국관광공사 등 공공 개방 데이터를 후보 원천으로 검토·활용한다. 실제 활용 범위는 각 데이터셋의 이용조건을 확인해 정한다. 원천 데이터만으로 모든 특성값과 목적을 확정할 수는 없으므로, 이 체계는 완성된 분류표가 아니라 원천 데이터 매핑·운영 검수·사용자 반응을 통해 계속 보정하는 기준이다.

일상에서는 사용자가 `카페 → 공부·작업 → 조용함 → 주차`처럼 세 축을 조합해 지도 후보를 줄인다. 여행에서는 동일한 정제 데이터를 각 슬롯의 후보군을 만드는 데 사용하고, 여기에 앞뒤 장소와의 이동시간·고정 장소·여행 시간을 추가로 반영한다. 즉 데이터 정제는 일상 기능만을 위한 작업이 아니라, 여행 코스 추천과 슬롯별 교체의 공통 기반이다.

## 5. 목적 기반 장소 카테고리: 내부 분류를 사용자 필터로 바꾸는 방식

내부적으로는 종류·특성·목적을 나눈 데이터 분류 체계다. 사용자에게는 이 복잡한 구조를 그대로 노출하지 않고, **상황과 목적을 해결하는 필터**로 제공한다.

기존 지도 앱에서 "카페"를 검색한 사용자는 이렇게 움직인다.

1. 사진을 보고 분위기를 확인하고
2. 리뷰를 읽으며 조용한지 확인하고
3. 콘센트가 있는지 후기를 뒤지고
4. 주차 가능 여부를 다시 검색하고
5. 그제서야 "여기가 내 목적에 맞는 곳인지" 판단한다.

우리 서비스는 이 과정을 뒤집는다. 처음부터 사용자의 목적에 맞게 장소를 좁혀서 보여준다. 아래는 데이터 정제와 목적 판정 규칙이 고도화됐을 때 제공할 사용자 필터의 예시다.

| 사용자 상황 | 추천 카테고리 |
| --- | --- |
| 조용히 책을 읽고 싶을 때 | 독서하기 좋은 카페 |
| 공부할 공간이 필요할 때 | 공부하기 좋은 카페 |
| 사진 찍기 좋은 곳을 찾을 때 | 감성카페 |
| 노트북 작업을 해야 할 때 | 작업하기 좋은 카페 |
| 차를 가져갈 때 | 주차 가능한 카페 |
| 친구와 오래 대화하고 싶을 때 | 대화하기 좋은 카페 |
| 빈티지한 옷을 사고 싶을 때 | 빈티지 옷가게 |
| 개성 있는 옷을 찾고 싶을 때 | 편집샵 |
| 혼자 밥을 먹을 때 | 혼밥하기 좋은 음식점 |
| 가족과 함께 갈 때 | 가족 모임하기 좋은 음식점 |
| 2차 장소를 찾을 때 | 분위기 좋은 술집 |

사용자에게 필요한 것은 더 많은 검색 결과가 아니라, "내 상황"이라는 몇 번의 선택만으로 원하는 장소에 도달하는 경험이다.

## 6. 일상: 지도 기반 목적지 탐색

일상 모드는 코스를 만드는 기능이 아니다. **지금 당장 가고 싶은 목적지 1개**를 더 정확하게 찾는 지도 기반 탐색 기능이다.

사용 방식은 네이버지도나 카카오지도와 같다. 지도를 열고 장소를 찾는다. 다른 점은 검색과 카테고리가 목적 중심으로 세분화되어 있다는 것이다.

예를 들어 카페를 찾을 때:

```text
지도 열기
→ 카페 선택
→ 공부하기 좋음 선택
→ 주차 가능 선택
→ 현재 위치와 가까움 선택
→ 조건에 맞는 카페 후보 확인
→ 목적지 1개 선택
```

옷가게를 찾을 때:

```text
지도 열기
→ 옷가게 선택
→ 빈티지 선택
→ 가격대 선택
→ 현재 위치와 가까움 선택
→ 조건에 맞는 빈티지 옷가게 확인
→ 목적지 1개 선택
```

핵심은 사용자가 장소를 많이 보는 것이 아니라, **자신이 원하는 목적에 맞는 후보만 좁혀서 보는 것**이다. 조건을 하나 선택할 때마다 지도 위의 후보가 줄어들고, 마지막에는 고민 없이 선택할 수 있는 몇 개의 장소만 남는다.

---

## 7. 여행: 슬롯 기반 코스 추천

여행 모드에서는 여러 장소를 하나의 흐름으로 연결한 코스를 추천한다. 이때 코스는 **슬롯(slot)** 단위로 구성된다.

슬롯은 여행 코스 안에 들어가는 하나의 자리다. 예를 들어 하루 여행 일정을 만들 때 사용자는 다음과 같은 자리를 설정할 수 있다.

```text
음식점 → 카페 → 관광지 → 술집 → 숙소
```

각 슬롯은 사용자가 자유롭게 구성할 수 있다.

| 슬롯 종류 | 설명 |
| --- | --- |
| 음식점 | 점심, 저녁, 혼밥, 데이트 식사 등 |
| 카페 | 감성카페, 독서 카페, 작업 카페, 대화하기 좋은 카페 등 |
| 관광지 | 여행지, 전시, 체험, 산책 장소 등 |
| 술집 | 2차 장소, 분위기 좋은 술집, 조용한 술집 등 |
| 숙소 | 호텔, 펜션, 게스트하우스 등 |
| 주차장 | 목적지 주변 주차 공간 |
| 산책/휴식 | 공원, 해변, 강변, 조용한 휴식 장소 등 |

여기서 중요한 것은 **모든 슬롯을 앱에 맡길 필요가 없다**는 점이다. 사용자가 이미 정한 장소는 고정할 수 있다. 예를 들어 숙소를 이미 예약했다면 숙소 슬롯은 고정하고, 잘 모르는 음식점·카페·관광지·술집만 추천받는다. 추천은 사용자의 계획을 대체하는 것이 아니라, 비어 있는 부분을 채워 주는 역할을 한다.

---

## 8. 여행 코스 수정: 슬롯별 재탐색과 교체

추천 코스가 100% 마음에 드는 경우는 많지 않다. 기존 방식이라면 코스 전체를 다시 추천받거나, 지도 앱으로 돌아가 처음부터 다시 검색해야 한다.

우리 서비스에서는 **마음에 들지 않는 슬롯만 교체**한다. 그리고 이 교체 과정은 일상 모드에서 사용하던 목적 기반 장소 탐색 엔진 그대로다.

앱이 다음 코스를 추천했다고 가정하자.

```text
음식점 A → 카페 B → 관광지 C → 술집 D → 숙소 E
```

카페 B가 마음에 들지 않는다면, 전체 코스를 다시 추천받는 것이 아니라 카페 슬롯만 선택해서 원하는 조건을 하나씩 적용하며 다시 탐색한다.

적용할 수 있는 필터 예시:

- 감성적인 분위기
- 조용한 공간
- 독서하기 좋음
- 작업하기 좋음
- 주차 가능
- 현재 위치와 가까움
- 다음 장소와 동선이 좋음
- 가성비 좋음

```text
추천 코스 확인
→ 카페 B가 마음에 들지 않음
→ 카페 슬롯 선택
→ 감성카페 + 조용함 + 주차 가능 + 다음 장소와 동선 좋음 조건 적용
→ 조건에 맞는 카페 후보 확인
→ 새로운 카페로 교체
→ 기존 여행 코스에 반영
```

이 흐름이 의미하는 바는 분명하다. 사용자는 추천 코스를 그대로 따르는 것이 아니라, **추천을 출발점으로 삼아 자신의 목적에 맞는 여행 코스를 점점 완성해 간다.** 이 서비스는 단순한 자동 추천 서비스가 아니라, **추천 + 사용자 선택 + 지도 기반 탐색**이 결합된 서비스다.

## 9. 대표 사용 흐름

**일상**에서는 사용자가 `카페 → 공부·작업 → 조용함 → 주차 → 가까운 거리`처럼 조건을 선택한다. 앱은 조건에 맞는 후보만 지도에 표시하고, 사용자는 그중 목적지 1개를 고른다.

**여행**에서는 숙소처럼 이미 정한 장소를 고정하고, 나머지 슬롯의 후보를 추천받는다. 추천된 카페가 마음에 들지 않다면 그 슬롯에서만 `감성 → 조용함 → 주차 → 다음 장소와의 거리` 조건을 다시 적용해 대체 후보를 고른다.

## 10. 장소 평가 기준

장소 추천은 리뷰 수나 평점만으로 결정하지 않는다. 다음 요소들을 점수화해 추천에 반영한다.

| 평가 기준 | 설명 |
| --- | --- |
| 위치 점수 | 현재 위치 또는 코스 동선과 가까운지 |
| 취향 적합도 | 사용자의 취향 조사 결과와 맞는지 |
| 목적 적합도 | 독서, 데이트, 혼밥, 작업, 쇼핑 등 목적과 맞는지 |
| 감성 점수 | 분위기, 인테리어, 사진 적합성 등 |
| 주차 편의성 | 자체 주차장 또는 주변 주차장이 있는지 |
| 가성비 | 가격 대비 만족도가 좋은지 |
| 동선 효율성 | 여행 코스에서 이전/다음 장소와 이동하기 좋은지 |
| 혼잡도 | 너무 붐비거나 대기 시간이 긴지 |

초기 추천은 위 요소를 종합해 후보를 정렬한다. 세부 가중치와 항목은 데이터 충족도, 사용자 피드백, 실제 이용 결과를 검증하며 조정한다. 따라서 이 문서에서는 특정 비율을 확정값으로 두지 않는다.

## 11. 주차 정보 제공

음식점, 카페, 관광지를 방문할 때 주차는 방문 자체를 좌우하는 조건이 되기도 한다. 그래서 장소를 추천할 때 다음 정보를 함께 제공하는 것을 목표로 한다.

- 장소에 자체 주차장이 있는지
- 주차 공간이 협소한지
- 주변에 공영주차장이나 유료주차장이 있는지
- 목적지와 주차장 간 거리가 가까운지
- 여행 코스 동선상 주차가 불편하지 않은지

특정 장소의 주차가 어렵다면 장기적으로 주변 주차장 후보까지 함께 연결한다. 예를 들어 자체 주차장이 없는 카페를 선택하면, 도보 거리의 공영주차장을 함께 안내하는 방식이다.

이 기능은 단순히 장소를 추천하는 것을 넘어, **사용자가 실제 방문 과정에서 겪을 수 있는 불편까지 줄이는** 요소다. 추천은 장소를 고르는 순간이 아니라, 도착해서 만족하는 순간까지 이어져야 한다.

## 12. 서비스 차별점

기존 지도 앱과 비교했을 때, 가보자GO의 차별점은 목적에 맞는 후보를 먼저 줄이고 그 탐색 기준을 여행 코스의 슬롯 추천과 교체까지 일관되게 활용한다는 점이다.

| 구분 | 기존 지도 앱 | 우리 서비스 |
| --- | --- | --- |
| 장소 탐색 방식 | 검색 결과를 많이 보여줌 | 목적에 맞는 후보만 좁혀서 보여줌 |
| 추천 기준 | 리뷰 수, 인기도, 광고, 알고리즘 영향 | 목적, 취향, 위치, 주차, 동선 등 종합 반영 |
| 카테고리 | 대분류 중심 | 사용자 상황 기반 세부 카테고리 |
| 일상 사용 | 장소 검색 후 직접 검수 | 목적지 1개를 필터링해서 빠르게 선택 |
| 여행 사용 | 장소를 개별적으로 찾아야 함 | 슬롯 기반으로 코스 추천 |
| 코스 수정 | 사용자가 직접 다시 검색 | 마음에 안 드는 슬롯만 재탐색 후 교체 |
| 핵심 가치 | 많은 정보 제공 | 필요한 정보만 정제해서 제공 |

## 13. 최종 목표

우리의 최종 목표는 사용자가 여러 지도 앱을 오가며 사진과 리뷰를 직접 검수하지 않아도 되는, **지도 기반 장소 탐색 및 여행 코스 추천 시스템**을 만드는 것이다.

> **우리는 장소를 '많이' 보여주는 서비스가 아니다.

# data-import 데이터 작업 기록 규칙

실측·정제·중복검증·entity resolution 등 `data-import/` 데이터 작업에서 **결과를 어디에
남길지**만 정한다. 이 문서는 아래 규칙 A~D만 소유한다.

다음은 여기서 다시 정의하지 않는다. 링크한 정본을 그대로 따른다.

| 주제 | 정본 |
| --- | --- |
| 결과·반례를 기록해야 한다는 원칙, 기존 판단이 틀렸을 때의 정정 절차 | [`L-1` §6](../../docs/L-1-operating-principles.md) |
| 마일스톤 종료 점검과 **작업 종료 보고 형식** | [`L-1` §7](../../docs/L-1-operating-principles.md) |
| 저장소 문서 정책·문서별 소유권 | [`AGENTS.md`](../../AGENTS.md) 문서 정책 |
| 원천 탐색 목적과 그 소유권 | [`other-source-survey.md`](other-source-survey.md) 0절 |
| 판단 변경 이력 | [`decision-log.md`](../../docs/decision-log.md) |

 ---

## A. 상세 검증 결과는 작업 직후 `data/reports/**`에 저장한다

실측·정제·중복검증·entity resolution에서 나온 상세 측정 결과는 작업 직후
`data-import/data/reports/**`에 **재현 가능한 형식**으로 저장한다.

```text
건수 · 채움률 · 중복률 · 순증률 · 좌표 이상 · 매칭 tier
false positive · reconcile 결과 · 표본 및 예외 사례
```

나중에 기억에 의존해 한꺼번에 복원하지 않는다.

정본 MD에는 상세 실행 결과 전체를 복사하지 않고 **현재 판단에 영향을 주는 핵심 결론만**
반영한다. 상세 수치가 필요하면 report 경로를 연결한다.

## B. owning document를 차수별 실행 로그 저장소로 쓰지 않는다

owning document를 `1차 결과 → 2차 결과 → N차 검증` 형태로 누적하지 않는다. 상세 실행
이력은 `data/reports/**`가 소유한다.

MD 문서는 **현재 유효한 결론**을 중심으로 유지한다. 새 검증으로 기존 결론이 갱신되면
무조건 새 절을 추가하기보다 **기존 현재 상태를 갱신할 수 있는지 먼저 검토한다.**

단, 판단이 바뀐 이유 자체가 이후 의사결정에 중요한 경우에는 `L-1` §6과 `decision-log`
정책에 따라 변경 근거를 보존한다.

## C. `raw` / `staging` / `reports` / `docs`의 역할을 섞지 않는다

| 계층 | 역할 |
| --- | --- |
| `data/raw/**` | 확보한 원본 사실 데이터. **원칙적으로 수정하지 않는다.** |
| `data/staging/**` | raw로부터 **재현 가능하게** 생성한 정제·표준화 결과 |
| `data/reports/**` | 실측·검증·정제 과정의 상세 근거와 측정 결과 |
| `docs/**` | 사람이 읽는 현재 결론·계약·운영 맥락·마일스톤 보고 |

같은 상세 데이터를 여러 계층에 불필요하게 복제하지 않는다.

## D. 정제·검증 로직을 바꾸면 결과도 같은 작업 단위에서 동기화한다

로직 변경으로 결과가 달라질 가능성이 있으면 아래를 같은 작업 단위에서 수행한다.

```text
1. 코드 변경
2. 관련 report 재생성
3. staging 영향이 있으면 staging 재생성
4. reconcile · 계약 테스트 재검증
```

코드만 바꾸고 이전 report를 최신 결과인 것처럼 남겨두지 않는다.

반대로 결과와 현재 판단이 바뀌지 않았다면 owning MD를 기계적으로 수정하지 않는다.

## 마일스톤 통합 보고서

`p1-data-source-report.md`처럼 **큰 단계의 결과를 새 개발자가 빠르게 이해하기 위한
사람이 읽는 산출물**은 허용한다. P1 종료·base staging 완료·expansion staging 완료·P2 종료
같은 단위에서 만든다.

**매 검증마다 생성하는 패턴으로 일반화하지 않는다.** 역할은 다음과 같이 나뉜다.

```text
상세 검증 근거          → data/reports/**
현재 운영·계약 상태     → owning MD
마일스톤 전체 이해용 요약 → milestone report
```

마일스톤 문서는 핵심 결과와 구조를 설명하고, 상세 근거는 가능한 경우 report 또는
owning document를 참조한다. report가 있으니 마일스톤 문서가 불필요한 것도 아니고,
마일스톤 문서에 report 내용을 전부 복사하는 것도 아니다.

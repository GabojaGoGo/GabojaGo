## 1. 한눈에 보는 P1 데이터 정제

P1의 목적은 확보한 원천을 곧바로 DB에 넣는 것이 아니라, 실제 파일을 열어 레코드 단위·상태값·좌표·중복·다른 원천과의 연결 가능성을 측정하고 원본과 정제 결과를 재검증 가능한 형태로 보존하는 것이었다.

현재 phase의 정본 판정은 **P1 데이터 정제 종료 승인, P2-A 진입 가능**이다. 이는 모든 애매함이 사라졌다는 뜻이 아니라, 확인된 결함은 정정했고 남은 애매한 사례는 잘못 합치지 않은 채 비차단 backlog 또는 P2/P3 책임으로 분리했다는 뜻이다.

```text
raw 확보
  → base staging
  → expansion staging
  → 상태 정규화
  → 좌표 검증
  → 원천 내부 확정 중복 정리
  → 원천 간 동일 장소 연결 검증
  → 최종 종료 감사
```

여기서 **staging**은 원본을 보존한 채 분석·후속 적재에 쓸 수 있도록 정규화한 중간 데이터다. **reconcile**은 정제 전후 건수가 제외·유지·중복 제거 내역과 빠짐없이 맞는지 검산하는 과정이다.

## 2. 데이터 구조

| 위치 | 역할 | 주의점 |
| --- | --- | --- |
| [`data/raw/**`](../data/raw/) | 다운로드한 원본 | 수정하지 않는다. 출처·해시·인코딩은 [`source-downloads.md`](source-downloads.md)가 소유한다. |
| [`data/staging/**`](../data/staging/) | 상태 정규화, 좌표 플래그, 제외 판단, 확정 중복 제거 등을 반영한 정제 결과 | DB의 최종 canonical Place가 아니다. 원천 사실과 provenance를 유지한다. |
| [`data/reports/**`](../data/reports/) | 실측·정제·중복·entity-resolution의 상세 근거 | 수치와 실행 결과의 정본이다. 사람이 읽는 문서에 같은 상세 수치를 반복하지 않는다. |
| [`docs/**`](.) | 현재 판단, 계약, 온보딩 설명 | 후보 상태는 survey, phase는 L0처럼 소유 문서가 나뉜다. |

raw와 staging은 용도가 다르다. raw를 직접 고치면 원천이 실제로 무엇을 제공했는지 재검증할 수 없으므로, 변환과 판단 결과는 staging의 별도 필드로 남겼다. reports는 그 변환이 누락 없이 수행됐는지 증명한다.

## 3. Base 원천 정제에서 한 일

Base 원천은 현재 모집단을 구성하는 출발점이다. 원천을 조사·평가한 이유와 현재 상태는 [`p1-data-source-report.md`](p1-data-source-report.md)와 survey §1을 보고, 이 절에서는 정제 의미만 다룬다.

- **LOCALDATA 음식·숙박 인허가**: 지역·업종 파일을 공통 staging 형태로 바꾸고 원문 상태를 `ACTIVE`, `CLOSED`, `SUSPENDED`, `UNKNOWN`으로 정규화했다. 원천 식별자가 실제 시설의 전역 고유키라고 가정하지 않았다.
- **상가(상권)정보**: 상태 컬럼이 없으므로 모든 행을 임의로 `ACTIVE`라고 단정하지 않았다. LOCALDATA와 연결되는 경우에도 다른 원천의 폐업 상태를 자동 전파하지 않고 근거를 별도로 유지했다.
- **TourAPI**: 콘텐츠 목록을 공통 구조로 바꾸고 주소·좌표 품질을 검사했다. 여행코스는 여러 지점을 묶은 일정이므로 단일 Place 모집단에서는 비장소 레코드로 제외했다. 원본 상세값은 임의로 보정하지 않았다.
- **전국주차장표준데이터**: 같은 관리번호가 여러 레코드에 나타나는 사례를 확인했다. 이름·주소·좌표·구획수 같은 추가 신호로 동일 시설 여부를 검증하고, 대표행을 고를 근거가 동률이면 자동 제거하지 않았다.

각 base 실행의 상세 건수와 검산 결과는 [`data/reports/cleaning/`](../data/reports/cleaning/)의 최신 `staging-*` 및 관련 감사 report가 소유한다.

## 4. 상태값 정규화

서로 다른 원천의 상태 표현을 비교할 수 있도록 다음 네 값으로 정규화했다.

- `ACTIVE`: 영업·정상 등 현재 운영을 명시하는 값
- `CLOSED`: 폐업·등록취소처럼 종료를 명시하는 값
- `SUSPENDED`: 휴업·영업정지처럼 일시 중단을 명시하는 값
- `UNKNOWN`: 상태가 없거나 어느 쪽으로도 안전하게 확정할 수 없는 값

원문 상태는 함께 보존한다. 상태 컬럼이 없다는 사실은 운영 중이라는 증거가 아니므로 `ACTIVE`로 추정하지 않는다. `전출`, `타시군구이관`, `영업개시전`, `조건이행완료`처럼 현재 4상태 중 하나로 단정하기 어려운 값도 원문을 남긴 채 `UNKNOWN`으로 둔다. 특히 관할 이전은 시설 폐업과 같은 사건이 아니다.

LOCALDATA에서 폐업으로 확인된 레코드와 상가정보 레코드가 비슷해 보여도, 두 원천의 레코드 단위·갱신 시점·식별 체계가 다르다. 그래서 LOCALDATA의 `CLOSED`를 상가정보에 그대로 전파하지 않았다. 원천 간 연결 후보와 원천별 상태 사실을 분리해야 정상 영업 중인 다른 점포를 잘못 닫는 일을 피할 수 있다.

## 5. 중복 정리에서 발견한 문제

중복 정리의 원칙은 **확정된 동일 시설만 제거하고, 애매하면 유지**하는 것이다. 같은 ID·이름·주소·좌표 중 하나만 같다는 이유로 자동 병합하지 않았다.

### 관광숙박업 관리번호

처음에는 같은 관리번호를 공유한 행을 한 시설의 이력으로 의심했지만, 실제 필드를 대조하니 서로 다른 시설이 같은 값을 쓰는 **source ID collision**, 즉 원천 식별자 충돌 사례가 있었다. 따라서 `같은 원천 ID = 같은 실제 장소`라는 규칙을 사용하지 않는다.

### 주차장

주차장 관리번호도 단독 고유키로 신뢰할 수 없었다. 이름, 지번·도로명주소, 좌표 거리, 구획수와 운영 정보를 함께 비교했다. 대표행 우선순위까지 같아 결론을 낼 수 없는 그룹은 보존했다.

### 표기 차이로 숨은 중복

비짓부산패스, 박물관·미술관, 농어촌체험휴양마을 등에서는 공백·하이픈·번지 표기 차이 때문에 문자열 완전일치만으로는 중복을 놓쳤다. 마지막 종료 감사에서도 주소 문자열은 다르지만 이름과 좌표가 같은 사례를 다시 확인했다. 이때도 층·호실 또는 하위시설 구분 신호가 있으면 합치지 않고, 실제 동일 시설로 확정된 경우만 staging에서 제거했다.

중복 제거 전후의 수치와 대표행 선정 근거는 cleaning reports에 남아 있어 `정제 전 = 최종 staging + 제외·제거` 관계를 다시 검산할 수 있다.

## 6. 좌표 품질 검증

좌표는 다음 상태로 플래그했다.

- `VALID`: 현재 부울경 검사 범위 안의 유효한 좌표
- `MISSING`: 위도 또는 경도가 없음
- `ZERO`: 0 좌표
- `OUT_OF_REGION`: 검사 범위 밖 좌표

TourAPI에서는 장소명과 주소는 부울경을 가리키지만 제공된 위도·경도가 실제 위치와 맞지 않는 사례가 있었다. 이는 장소 자체가 부울경 밖이라는 결론이 아니라 **원천 좌표값의 품질 문제**다. P1은 이 사실을 플래그하고 원문을 보존했으며, 지오코딩 등으로 원본 좌표를 자동 덮어쓰지 않았다.

LOCALDATA의 투영좌표처럼 좌표계 변환이 필요한 경우에도 변환 결과와 원천 좌표를 구분했다. 변환·범위 판정 로직은 공용 정제 모듈을 사용해 분석과 staging 생성이 서로 다른 규칙을 쓰지 않도록 했다.

## 7. 국가유산 영역형 데이터 처리

국가유산 일부는 지도에서 점 하나가 아니라 경계를 가진 **polygon(영역 데이터)**으로 제공된다. 하나의 장소가 떨어진 여러 영역으로 구성된 **multipart geometry(여러 조각으로 된 영역 형태)**도 존재한다.

기존 중심점 계산은 오목하거나 여러 조각인 영역에서 대표 좌표가 실제 영역 밖으로 나갈 수 있었다. 정제 과정에서 SHP의 외곽선과 구멍을 올바른 `Polygon`/`MultiPolygon`으로 구성하고, 대표점이 실제 영역 내부에 있도록 보장하는 방식으로 교체했다. 생성 실패·멀티파트 여부 같은 진단 정보도 report에 남겼다.

이 대표점은 지도와 원천 간 비교를 위한 P1 관측값이다. 넓은 국가유산을 최종 서비스에서 점형 Place로 어떻게 표현할지는 P2/P3의 별도 결정이다.

## 8. Expansion staging

P1 확장 탐색은 후보를 발견하거나 문서만 확인한 데서 끝내지 않았다. 원본을 확보하고 확장 후보로 판단한 범위는 staging 생성, 상태·좌표 검사, 내부 중복 점검, raw 대비 completeness 감사까지 진행했다. 최신 후보 목록과 상태는 이 보고서가 아니라 [`other-source-survey.md` §1](other-source-survey.md#1-tourapi의-역할--전체-기준선이-아니라-관광-콘텐츠-원천)이 소유한다.

staging된 확장 원천군에는 다음이 포함된다.

- 국가유산, 관광안내소, 박물관·미술관, 문화시설, 공공미술
- 공공·인허가 체육시설
- 전통시장, 도시공원, 휴양림
- 숙박 관련 LOCALDATA 확장 업종과 야영장
- 농어촌체험, 마리나, 어항, 낚시터, 산림·치유 관련 시설
- 비짓부산패스와 그 밖에 survey §1에서 원본 보존·staging 대상으로 확정한 원천

여기서 **실측 완료**, **staging 완료**, **채택**은 서로 다르다. 측정했다는 사실만으로 최종 적재 원천이 되는 것은 아니며, 최신성·이용조건·비용·다른 원천 대비 가치까지 survey의 현재 상태 판정에 따른다.

## 9. 서로 다른 원천의 같은 장소 연결

**Entity resolution**은 서로 다른 원천의 레코드가 같은 실제 장소를 가리키는지 찾는 작업이다. 예를 들어 TourAPI, 박물관 표준데이터, 울산 문화시설 데이터에 각각 있는 `울산대곡박물관`이 한 장소인지 대조하는 일이다.

P1에서 검증해 link 후보 생성에 적용한 고신뢰 규칙은 두 가지다.

- **Rule A**: 정규화한 이름이 완전히 같고 좌표 거리가 30m 이내
- **Rule B**: 정규화한 이름이 완전히 같고 숫자를 포함한 정밀 주소가 완전히 일치

주소가 시·군·구나 읍·면·동 수준에 그치는 경우에는 Rule B의 정밀 주소로 보지 않는다. 넓은 장소는 30m 규칙에서 자동 제외한다.

이 규칙의 출력은 실제 DB 병합 결과가 아니라 **같은 장소일 가능성이 높은 연결 후보**다. **Cardinality**는 한 레코드가 상대 원천의 몇 레코드와 연결되는지 나타내는 `1:1`, `1:N`, `N:1`, `N:N` 관계 형태다. 여러 원천에 정상적으로 하나씩 연결된 경우와 한 원천 내부 중복·복합시설 때문에 여러 건에 연결된 경우를 구분해 감사했다. 실제 `canonical_place_id` 생성과 병합은 P3 책임이다.

## 10. 자동으로 합치지 않은 것

### 복합시설

같은 주소와 좌표에 있어도 생활체육관, 수영장, 테니스장처럼 시설유형이 다르면 한 건으로 합치지 않았다. 하나의 건물·부지와 서비스가 노출할 장소 단위가 반드시 같지는 않기 때문이다.

### 면적형 장소

산, 공원, 해수욕장처럼 범위가 넓은 장소는 입구·대표점·관광 콘텐츠 좌표가 서로 떨어질 수 있다. 점형 시설용 30m 규칙을 그대로 적용하지 않고 검토 대상으로 분리했다.

### 공공미술

작품 하나를 독립 Place로 볼지, 공원·시설의 하위 콘텐츠로 볼지는 데이터 정제가 아니라 서비스 분류 문제다. 원천과 staging은 보존하되 P2 판단으로 넘겼다.

### 판정보류 중복 후보

이름과 좌표가 가까워도 층·호실, 세부 주소, 시설유형 등 구분 신호가 있거나 근거가 부족하면 자동 병합하지 않았다. 과소 병합은 후속 근거로 다시 검토할 수 있지만, 잘못 합친 레코드는 원천별 사실과 상태를 잃기 쉽기 때문이다.

## 11. 정제 과정에서 발견·수정한 주요 버그

- **확장 LOCALDATA 상태 어휘 누락**: base 업종에 없던 `정상`, `지정`, `폐업처리` 등의 실제 값이 공용 `STATUS_MAP`에 빠져 있었다. 확장 업종의 상태 어휘를 전수 대조하고, 의미가 확정된 값만 매핑했다.
- **국가유산 대표점 계산 오류**: 멀티파트·오목한 polygon에서 단순 중심점이 영역 밖에 생겼다. 실제 geometry를 구성한 뒤 영역 내부 대표점을 사용하도록 바꿨다.
- **`is_area_name()`의 `산` 오판**: 단순 부분문자열 검사는 `부산`, `울산`이 들어간 점형 시설까지 산으로 분류했다. 독립된 산 이름이나 접미 형태만 판정하도록 범위를 좁혔다.
- **충돌 주석의 정상 연결 오분류**: 한 레코드가 서로 다른 여러 원천에 정상적으로 연결된 경우까지 충돌로 셌다. 같은 상대 원천 안에서 여러 레코드와 연결될 때만 cardinality 충돌로 보도록 고쳤다.
- **주소 완전일치 dedupe의 누락**: 번지·호·공백·하이픈 표기 차이가 있는 확정 중복을 놓쳤다. 이름·좌표와 주소 구분 신호를 함께 재검증하되, 확정할 수 없는 후보는 유지했다.
- **실행 의존성 누락**: 좌표 변환·SHP·geometry 처리가 사용하는 `pyproj`, `pyshp`, `shapely`가 프로젝트 의존성에 빠져 재현 가능한 실행을 막았다. 사용 코드와 의존성 선언을 맞췄다.

이 문제들은 예제만 보고 찾은 것이 아니라 실제 raw→staging 검산과 원천 간 link 충돌을 재검토하는 과정에서 발견됐다. 따라서 코드 수정 뒤 report와 staging을 다시 생성하고 최종 감사를 반복했다.

## 12. 최종 종료 감사

최종 근거는 [`p1-cleaning-final-closure-audit-20260826.md`](../data/reports/p1-cleaning-final-closure-audit-20260826.md)와 그 문서가 가리키는 reports다. 상세 수치를 이 보고서에 복제하지 않고 종료 의미만 요약한다.

- survey §1과 실제 staging을 대조했을 때 설명 없는 미staging 확장 대상이 없다.
- base와 expansion의 raw→staging reconcile이 통과했다.
- 실측된 상태 어휘가 의도한 네 상태로 처리되며, 우연히 `UNKNOWN`이 된 값이 없다.
- 원천 내부에서는 확정 동일시설만 제거했고 복합시설·면적형·판정보류 후보는 유지했다.
- 원천 간 entity-resolution의 다대다 관계를 확인했으며 설명 불가능한 충돌을 남기지 않았다.
- raw 데이터 파일은 정제 과정에서 변경하지 않았다.
- 남은 항목은 P1 종료를 막지 않는 관찰 backlog 또는 P2/P3 후속 책임으로 구분됐다.

따라서 현재 정본 상태는 **P1 데이터 정제 종료 승인**이다. 과거 종료 판정이 staging 누락 때문에 철회됐다가 전량 보완 후 재확정된 이력은 [`decision-log.md`](../../docs/decision-log.md)에 남아 있으며, 이번 보고서는 그 이력을 지우거나 별도 현재 상태로 대체하지 않는다.

## 13. 남은 backlog와 다음 단계

### P1 종료를 막지 않는 장기관찰·판정보류

- TourAPI 호출 쿼터가 회복된 뒤 필요한 상세 재측정
- 시간 간격을 둔 인허가 원천 재관측
- 추가 구분 신호가 없어 자동 병합하지 않은 중복 후보

이 항목의 정확한 현재 상태와 재개 조건은 L0 §6 및 survey §1을 따른다.

### P2에서 결정할 것

- `PlaceType`/`PlaceSubtype`과 원천 분류값의 매핑
- 축제·공연 같은 Event와 Place의 경계
- 면적형 장소, 공공미술 작품, 복합시설과 하위시설의 표현 단위
- 체험+숙박, 캠핑 등 애매한 장소군의 taxonomy

### P3에서 구현할 것

- `canonical_place_id`와 실제 cross-source 병합 구조
- 대표 필드 선택 우선순위와 provenance 보존 방식
- DB schema, importer, 수집·갱신 실행 구조

P1 결과는 위 결정을 위한 관측 근거이지, P2 taxonomy나 P3 구현 계약을 미리 확정하지 않는다.
